# 退役构建机镜像层复用配对（layer-matcher）

CI 值班员工具，包含两块能力：

1. **镜像层配对**：构建机退役后，找出待重跑任务能从哪些**在役构建机**复用镜像层。
   上传两份 CSV，系统按"层摘要"做等值连接，把相同摘要在两表中的**所有行对**列出，
   每对只出现一次，产出 `任务号, 来源构建机, 层摘要` 清单 CSV。
2. **预热批次调度**：在**已完成的配对作业页**选一台目标机，上传含
   `层摘要, 字节数` 的层大小 CSV 并填写本轮拉取上限（字节预算），随后按任务号
   申请入批/撤销；系统按 FIFO 放行并严格核算待拉字节，避免拉取的镜像层超出预算。

## 需求对照

| 要求 | 实现 |
| --- | --- |
| Flask 网页上传两份 CSV | `app/app.py` + `app/templates/`，支持中文/英文列名别名 |
| 相同摘要所有行对、每对一次 | 分桶 + 分块嵌套循环等值连接，输出前不做去重、不丢行（自测校验唯一性） |
| 内存最多暂存 256 条输入记录、256 条结果 | 每侧块大小 128（合计 256）；结果满 256 立即刷盘；`BoundedMemoryGuard` 运行时强制，越界即抛异常；自测断言整次运行峰值 |
| 只统计重启后仍能保留的配对 | 配对数始终由磁盘上已确认的结果批次重数（`count_pairs_on_disk`），不依赖内存 |
| 写盘中断可续跑、已确认批次不重算 | 工作单元 = (桶, 任务块, 机器块)；单元结果原子写盘后才推进 `state.json`（原子 rename + fsync）；续跑按状态跳过已确认单元，重算前清理本单元残留 |
| 全部完成后才开放 CSV 下载 | 仅当最终 `pairs.csv` 生成后下载路由返回 200，否则 409 |
| 清单列出任务号、来源构建机、层摘要 | 最终 CSV 表头即这三列 |
| Docker Compose 启动 | `docker compose up --build`，命名卷 `layer_matcher_data` 持久化断点状态 |

## 预热批次调度（`app/prewarm.py`）

仅在配对作业 `phase=done` 后开放，每个作业**只建一批**（重复建批返回 409）。

### 需求对照

| 要求 | 实现 |
| --- | --- |
| 已完成作业页选目标机、传层摘要+字节数 CSV、填拉取上限 | 作业页建批表单；目标机下拉来自作业缓存表 `machines.csv`；字节数支持 `1024`/`2mb`/`3GiB` 写法 |
| 目标机已有层免计 | 放行记账时跳过 `machines.csv` 中该目标机已缓存的摘要 |
| 入批任务共用缺层只计一次 | 以待拉层**并集**记账（`admit_sweep`），每层在清单中恰好一行，列出共用任务 |
| 待拉层大小未知 → 说明原因并拒绝 | 申请时预检，拒绝信息列出全部未知摘要，任务不进队列，拒绝原因落盘 |
| 单任务待拉量本身超预算 → 拒绝 | 入队前先算单任务独占口径字节数，超预算直接拒绝并写明数值 |
| 每次申请/撤销后从队首依次放行 | `admit_sweep` 按队列 FIFO 扫描；队首放不进立即停止（队首阻塞），其后任务继续等 |
| 撤销后其余任务仍需的缺层继续占预算 | 撤销后基于剩余队列重算并集，只释放无人再用的层，再从队首补位 |
| 重复申请沿用已有登记 | 任务已在队列中时不改顺序、不重复登记，返回 `duplicate` 结果 |
| 并发下三者一起生效且总量不超预算 | 进程内 `RLock` + 作业级 `flock` 文件锁；队列/入批名单/缺层清单在同一临界区计算并同一次原子落盘 |
| 写失败或重启后可查最近一次成功结果 | 所有状态写 `prewarm/state.json`（临时文件 + fsync + `os.replace`）；写失败旧文件不动；`last_result` 记录最近一次成功操作 |
| Docker Compose 启动 | 见下文，命名卷 `layer_matcher_data` 同时持久化配对与预热状态 |

### 落盘结构（每个作业目录下）

```
<prewarm/>
  state.json   # 权威状态：target/budget/sizes/queue/admitted/last_result
  sizes.csv    # 建批时上传的层大小表（留存审计）
  .lock        # 作业级 flock 文件
```

页面与 `GET /jobs/<id>/prewarm/status` 展示：目标机、预算、已用/剩余字节、
FIFO 等候顺序、入批任务、等候任务、待拉层清单（含每层字节数与共用任务）、
队首阻塞任务、最近一次成功操作结果。

## 算法与内存边界（`app/join_engine.py`）

1. **分桶（partition）**：流式读两份 CSV，用跨进程稳定的 FNV-1a 哈希把记录路由到
   64 个磁盘分桶文件；该阶段内存只持有当前 1 条记录。
2. **分块嵌套循环连接（block nested-loop join）**：逐桶处理，每侧每次最多载入
   128 条（两侧合计 ≤ 256 条输入记录），任务块 × 机器块做笛卡尔匹配。
   热点摘要（同摘要海量行对）只会产生更多磁盘结果批次，内存驻留不增长。
3. **结果刷盘**：结果缓冲每 256 条原子写一个批次文件（临时文件 + `os.replace`），
   内存中结果永不超过 256。
4. **断点续跑**：每个 (桶, 任务块, 机器块) 单元完成并刷盘后，原子更新 `state.json`
   记录游标；进程重启后从磁盘状态恢复，跳过已确认单元。分桶阶段中断则整侧重写
   （先删旧分桶文件），join 阶段中断只重算未确认的当前单元。
5. **最终合并**：流式拼接所有批次为 `pairs.csv`，不整体载入内存。

## 目录结构

```
app/
  app.py            # Flask 路由、后台线程、启动恢复、下载门禁、预热批次路由
  join_engine.py    # 受限内存外部连接引擎（分桶 + 分块 BNLJ + 断点续跑）
  prewarm.py        # 预热批次调度（FIFO 放行、缺层并集记账、flock 并发、原子落盘）
  templates/        # 上传页 / 作业详情页（含预热面板）/ 错误页
  Dockerfile
  requirements.txt
cli/run.py          # 命令行入口，支持 --crash-after 故障注入
tests/              # unittest 自测（引擎 7 + 预热引擎 16 + Web 配对 3 + 预热 Web 8）
examples/           # 任务/构建机/层大小三份示例 CSV
docker-compose.yml
```

## 用 Docker Compose 启动

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

作业数据写入命名卷 `layer_matcher_data`（容器内 `/data/jobs`）。
容器/进程重启后，中断的作业会在首次访问时自动从断点继续，已确认批次不重算。

## 本地开发与自测

无需 Docker（本机无容器运行时时）：

```bash
# 安装 Flask 到独立目录（不污染系统环境）
python3 -m pip install --target=.pylibs flask==3.0.3   # 或使用已有的 get-pip

# 引擎自测（仅标准库，不需要 Flask）
python3 -I -m unittest discover -s tests -t .

# 含 Web 层的全部自测
PYTHONPATH=.pylibs:app python3 -m unittest discover -s tests -t .

# 命令行跑一个作业（作业目录内需有 tasks.csv / machines.csv）
PYTHONPATH=.pylibs:app python3 -I cli/run.py /path/to/job
# 故障注入：第 N 个检查点模拟写盘中断（退出码 3），再次执行即续跑
PYTHONPATH=.pylibs:app python3 -I cli/run.py /path/to/job --crash-after 1610
```

## 输入 CSV 格式

- 任务表：`任务号, 层摘要`（别名：task_id/job/task + digest/layer/sha256/hash）
- 构建机表：`来源构建机, 层摘要`（别名：machine/host/builder + digest/...）
- 层大小表（预热建批时上传）：`层摘要, 字节数`（字节数列别名：size/bytes/...；
  支持 `1024`、`2mb`、`3GiB` 等单位写法；同摘要大小冲突会被拒绝）
- 空摘要行无法参与等值连接，会跳过并在作业页计数展示。

## 自测覆盖（34 项，全部通过）

**配对（10 项，原有）**

- 正确性：多摘要全部行对、每对一次；空摘要跳过；无匹配产出仅表头文件
- **热点摘要**：600×600 同摘要（36 万对）+ 冷数据，注入内存守卫跑完整流程，
  断言输入记录峰值 ≤ 256、结果峰值 = 256（达上限即刷盘）
- **中断续跑**：进程内故障注入后续跑结果与一次跑完一致；
  两个独立子进程模拟真实写盘中断与重启接力；第三次执行验证幂等无重复；
  分桶阶段中断同样可恢复
- Web：上传→状态轮询→完成前下载 409、完成后 200 且列名正确；
  坏表头 400；构造 joining 中断态后调用启动恢复，已确认批次保留
- 真实 CLI 冒烟：800×800 数据在 join 阶段中断（4711 条已确认），
  新进程续跑至 17306 条，与手工期望值一致且无重复

**预热批次（24 项，新增）**

- 引擎（`tests/test_prewarm_engine.py`，16 项）：缓存层免计与共用缺层只计一次、
  FIFO 队首阻塞、未知大小拒绝（含原因落盘）、单任务超预算拒绝、重复申请幂等、
  每作业一批/目标机校验、**撤销后共用层继续占预算并从队首补位**、
  写盘失败保留最近一次成功状态、重启重建视图、字节单位与大小表解析、
  8 线程并发申请（预算恰好打满不超限、入批为队列前缀、缺层清单可对账）、
  并发申请+撤销不变量、**6 子进程并发申请验证 flock 跨进程串行化**
- Web（`tests/test_prewarm_web.py`，8 项）：完整 HTTP 建批/申请/撤销流程与页面渲染、
  HTTP 层拒绝提示、共用缺层撤销补位、二次建批 409、作业未完成建批 409、
  模拟重启后状态可查、8 客户端并发申请不超预算、并发申请+撤销后补位自洽

> 另做过两次真实运行冒烟：Flask 开发服务器 + curl 全链路（含重启后状态保留），
> 以及多进程 curl 并发申请/撤销压测，预算、队列前缀、缺层清单三个不变量均成立。

## 已知限制 / 剩余事项

- 当前交付环境没有 Docker 守护进程，`docker compose up` 仅做了 compose/Dockerfile
  静态校验，未实际构建镜像；需在有 Docker 的环境执行一次冒烟。
- 容器内用 Flask 自带开发服务器（单进程多线程，符合"同进程后台线程 + 状态文件"
  的设计）；预热操作额外用 `flock` 保证多进程/多 worker 下也串行，
  但配对引擎的作业级分布式锁仍建议上 gunicorn 时限定单 worker。
- 上传大小上限 50MB（`app.py` 中 `MAX_UPLOAD_BYTES` 可调）。
- 预热预算与字节数均按非负整数（1024 进制单位）核算；不支持十进制（1KB=1000）口径。
